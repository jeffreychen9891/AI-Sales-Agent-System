# 工程笔记

这份文档不讲架构 —— 架构在 [README](../README.md) 里，而且**架构图谁都能画**。

这里讲的是另一件事：这个仓有一套**会在判断失效时变红的守卫**，
而下面这**十二条缺陷全部发生在这个仓的守卫与工具自己身上**。
逐条带坐标、带代价、带修法。

它们是怎么被发现的，我分开标注，因为这件事本身就是结论：

* **九条是守卫自己报出来的** —— 它们咬到了写它们的人；
* **第 10 条是人读出来的**，守卫当时全绿。它标出的是这套做法**不能**替代什么；
* **第 11 条是在 `git commit` 前一刻数出来的** —— 两个数差了 1。
  它是唯一一条**本来一定会发出去**的，所以我把它放在最显眼的位置；
* **第 12 条是在给演示接线时撞到的** —— 一张为「别写死某个名字」而建的查表，
  **自己有两个调用点写死了那个名字**。

我认为这十二条比任何架构图更能说明一个人怎么写代码，因为它们**没法伪造**：
你得先给自己定下判据，再让它来咬你。

> **先说一件事，以免你去找一个不存在的文件。**
> 下文反复提到的那个导出工具（`scripts/export_portfolio.py`）与钉它的 25 条用例
> **不在这个仓里** —— 它持有禁用词表，所以它的存在会让它自己的第 2 道闸必响
> （这正是下面第 7 条那一族）。它留在私有一侧。
> 本仓纪律里有一条："**一条指着不存在坐标的标记比没有标记更糟**，
> 因为下一个人会照着它去找，找不到，然后自己造一遍"。所以这里先说清楚。

## 一 · 最贵的那一族：一个判据的两个半边

> **唯一定义点让两边永远一致 —— 包括一致地错。**

这是教科书会夸的那种设计（DRY、单一事实来源），而它有一个教科书不讲的失效模式：
当两个半边共用一个**错的**判据时，它们**一致地错**，于是没有任何对比能发现它。

### 1. 没有后缀的文件既不被改写，也不被扫描

一个工具要做两件事：把文件里的供应商名改掉，然后扫一遍确认没漏。
两件事各自问"这是文本文件吗"，**各自按后缀判**。

于是 `.gitignore`、`Dockerfile`、`.gitattributes` 这类**没有后缀**的文件
两边都认不出来：不被改写，**也不被扫描**。

实测残留就一处 —— `.gitignore` 第 38 行那个供应商文件名，**而扫描一声不响**。

**修法不是补两个名字**，是把判据收成一个函数 `is_text()`，让两边只能一起对
或一起错；然后补一条**不用这个函数**的用例：它把导出清单里所有没有后缀的文件
列出来逐个问。**一条用判据的 + 一条不用判据的**，这是这个盲区唯一的解法。

### 2. 复用一套规则时，豁免也是规则的一部分

密钥扫描复用了另一个脚本的规则表 —— 很好，不另写一份，否则两处迟早只改一处。

然后它报了 20 条命中，**全部是假的**：那 20 条都来自被复用那个脚本自己的
`ALLOWED_PATHS`（两个按设计持有合成凭据形状的文件）。

规则被复用了，**豁免没有**。而"一套规则"包含它的豁免。

### 3. 一个半边凭记忆复述另一个半边（这一条最贵）

导出工具里有一条"连带排除"规则：一个用例如果去读一个被扣下的文件，
它自己也不能导出，否则导出树里会留下一条读不到文件的红用例。

这条规则靠**手列的拼法**去判断"什么算被扣下的东西"：
三个大写根变量名（`ROOT` / `REPOSITORY_ROOT` / `REGRESSION_ROOT`）
加两个目录名（`docs` / `evidence`）。

它有四个各自独立的盲区，实测**全部咬到了**：

| 盲区 | 后果 |
|---|---|
| 只认那两个目录，不认别的排除规则扣下的东西 | 22 条红 |
| 只认那三个变量名 | 一个用例写的是内联的 `Path(__file__).resolve().parents[2] / "docs" / ...` —— 根表达式没有名字，整条规则看不见 |
| 对数据文件也生效 | 见下面第 6 条 |
| 配套的 import 闭包对带点 import 失明 | 见下面第 4 条 |

实测代价：**导出树采集全通，而跑起来 25 条红。**

**真因不是正则写窄了，是这条规则在重新推导一件工具自己已经算出来的事。**
哪些文件出得去，选择函数已经返回了；这条规则却去**猜那个集合长什么样**。

这比第 1 条贵，因为它不是"两个半边共用一个判据"——
是**一个半边凭记忆复述另一个半边**，而记忆会漏。

**修法：不猜，去问。** 把代码里每一条像仓内路径的东西解出来，
然后问**真实的导出集合**"这个文件出去了吗"，跑到不动点。
于是排除规则加一条、分类表改一个定性，**连带关系自动跟着变，没有第二张表要同步**。

顺带一提，它还解掉了原规则担心的那个误伤。原注释写着"区分 `ROOT / "docs"` 与
`tmp_path / "docs"` 是承重的，后者是用例自己造的临时树"——
而新判据要求候选路径是一个**真实被 git 跟踪的文件**，临时树里的文件不被跟踪，
所以自然不连带。**原规则是用拼法替判据，新判据直接问事实。**

## 二 · 第二族：错的方向是安静的

能建成、能写入、能返回 200，**只有结果是错的**，而没有任何东西变红。
这类缺陷靠人查最贵。

### 4. 一条正则对整整一类语法结构性失明

那个 import 闭包要找出"import 了一个已经走掉的模块"的文件。它的正则是：

```
from\s+([A-Za-z_][A-Za-z0-9_]*)\s+import
```

模块名后面**要求紧跟空白**。于是 `from scripts.check_static import X` 里那个点
把整条规则挡在门外 —— 它对**所有**带点的 import **结构性地失明**。

而失明的方式是安静的：**闭包照样报"已跑到不动点"，只是那个不动点是错的。**
实测后果是导出树里一个用例文件采集即 `ModuleNotFoundError`。

讽刺的是，**这正是那条正则自己的注释警告过的那一种**。原注释写着：

> 一个只认 `test_` 前缀的闭包会在第二层停下，而"停在第二层"与"跑到不动点"
> 在输出上长得一样：都是"没有新的了"。

它把这个形状想清楚了、写下来了，然后**在同一段代码里以另一种方式犯了它**。
想清楚一个失效模式，不等于你的实现躲过了它。

**修法**：补一条认带点 import 的规则，并且**按路径认而不是按模块名末段认** ——
这个仓有多个 `conftest.py`，按末段判会让其中任意一个的离开带走所有
`from tests.conftest import`。

### 5. 过宽的判据会把一对东西拆成一半

那条"谁读了被扣下的文件"的规则，初版对**所有文本文件**生效。

于是一份测试夹具 `commands.json` 被带走了 —— 因为它的 provenance 注记里
有一个字面量路径串，指向它自己的出处。

**而读这份夹具的那个用例留下来了。** 导出树里于是有一条必红的用例。

这条闸漏的不是"少带一个文件"，是**把一对东西拆成了一半**。

两件事长得一样而处置方向相反：

| | 它是什么 | 怎么办 |
|---|---|---|
| 一份**数据**引用了自己的出处 | 溯源注记 | **留下它**，改写那句话 |
| 一份**用例**去读一个被扣下的文件 | 真实依赖 | **它跟着走**，否则导出树是红的 |

分开它们的判据是"**构造并读取路径的是代码，不是数据**"，
所以这条规则的适用范围收到 `.py`。

同一族还有一次：这条规则初版对全树生效，把一个**生产模块**带走了 ——
那个模块只是在**注释里提了一句**被扣下的东西，而它是发布链路的依赖，
导出树一跑就 `ModuleNotFoundError`，连 conftest 都加载不了。
**生产源码里的"提到"与用例里的"读取"，处置方向同样相反**：
前者改那句话，后者跟着走。

## 三 · 第三族：描述一个东西的行为，不要产生那个东西

### 6. 工具自己印着它要查禁的那张词表

那个导出工具持有禁用词表（供应商名、客户行业词、内部仓名）。
于是**它的存在本身就让它自己的第 2 道闸必响**。

### 7. 清单文件把"从什么改来"写进了公开树

工具会在导出树里写一份 `EXPORT-MANIFEST.json`。初版把**整张改名表**写了进去 ——
包含每一个原词。扫描当时全绿，因为**清单是在扫描之后才写的**。

两条修法：
* **清单先写，再扫** —— 否则扫描看不见工具自己写进去的文件；
* **清单只记"改了多少处、改成什么"，不记"从什么改来"。**
  需要原词的那份审计写到导出树**外面**。

这两条是同一个形状的第四次和第五次。一个脱敏工具最容易泄露的东西，
是**它对脱敏这件事的描述**。

## 四 · 第四族：失效的规则比没有规则更糟

### 8. 两条排除规则什么都没在挡

排除表里有 `node_modules/` 和 `dist/`。它们**一个文件都没在挡** ——
导出的文件来源是 `git ls-files`，而那两个目录早就被 `.gitignore` 挡在清单之外了。

一条**已经失效**的排除规则比没有规则更糟：它让人以为某个东西被挡住了。

**修法是一条用例，而它的失败语义很重要**：
*"每一条排除规则都必须还指着真东西。"*
这条红的时候**不是坏了，是到期了** —— 某个被排除的东西改名或移走了，
处置是去看那一条规则。报错里就这么写着。

> **不要把它改成"至少有一条匹配"** —— 那正是让失效规则活下来的写法。
> 这个仓里这类表全部是**等值判**，不是包含判：
> 新增一个顶层目录必须让导出**当场拒绝**，没有"悄悄跟着出去"和"悄悄被漏掉"的第三种。

## 五 · 第五族：字节口径

### 9. 等长替换保住字节测量，保不住哈希

这个仓里有不少断言绝对字节数的用例（提示词预算、请求下限、素材字节上限）。
改名会动字节，所以改名可能让它们变红。

**一条看起来很聪明的省事路子：等长替换。** 长度不变 → 所有字节测量不变。

实测把它否掉了一半：这次的改名恰好**就是等长的（7 ↔ 7 个字符）**,
字节断言全绿 —— 而一个配包的 `content_hash` **当场红**，
因为被改的那段字节**在被哈希的范围里**。

**等长替换救的是字节断言，不是哈希。** 两者要分开想。

这一条还有一个直接后果：有一条"把配包目录名改成一个自述占位名"的改名规则
被删掉了 —— 不是因为那个名字不合适，是因为**那个名字就是被 `content_hash`
盖住的那段字节**，改它会让导出树当场红。

### 10. "保守"不能替代"去看一眼"（**这一条守卫没报，是人读出来的**）

有一个演示用的配包，第一轮按"可逆优先"把它整个扣下了：
**公开不可逆，少掉一些用例可逆**，所以保守是对的决策方向。

代价量出来是 **454 条用例**（占那一层的 17%，38 个用例文件）。

后来发现：**那条排除理由是错的。** 它是从**文件名和两句摘录**推出来的
（"看起来像前雇主的定价与销售话术"），而不是从内容读出来的。
真去读：29 条素材的 id 全部是 `demo-` 前缀，正文是通用演示文案,
**没有公司名、人名、手机号、邮箱、长数字 id**（逐条扫过，0 命中）。

**决策方向是对的，而那条理由没有被核。** 保守不能替代去看一眼 ——
它只是让"没看"的代价变成 454 条用例，而且是**沉默的**：
一个悄悄少了 454 条用例的导出，读起来和"这个项目只有这么多用例"一模一样。

所以那个工具有一条硬规矩：**不许静默截断。** 扣下的每一个文件都要
**逐个带着触发它的那个词**进审计报告 —— 一个只给总数的报告
答不了"为什么少了这一条用例"。

## 六 · 第六族：导出干净，不等于到得了公开仓

### 11. 公开仓的第一笔提交悄悄少了一个文件（**差点就发出去了**）

三道闸全绿、文件数对得上、2084 条用例全过。然后在 `git add -A` 之后
我顺手比了两个数：

```
磁盘上的文件   666
git 暂存的     665
```

**差一个。** 那一个是 `infrastructure/local/compose.yml` ——
**而 README 正好叫读者去 `docker compose -f infrastructure/local/compose.yml up`。**

成因是一条两个字符的疏漏。`.gitignore` 第 48 行是：

```gitignore
local/
```

不带前导斜杠的 gitignore 模式**匹配任何层级上的同名目录** ——
它的本意是顶层那个 `local/`（存放本地凭据，不公开），
而它顺手也匹配了 `infrastructure/local/`。

在原仓里这件事看不出来：那个 compose 文件**被 force-add 过**，
所以它在索引里、`git ls-files` 列得出它、导出会复制它。
**而公开仓是全新历史** —— 没有索引，只有规则，于是规则赢。

这一条我最在意，因为它**每一道现有的闸都挡不住**：

| 闸 | 它问的问题 | 能不能挡住这个 |
|---|---|---|
| 顶层分类 / 禁用词 / 密钥扫描 | 导出的内容**干不干净** | ❌ |
| 用例跑一遍 | 导出的代码**对不对** | ❌（那个文件是 compose，没有用例读它） |
| 文件计数 | 导出了**多少个** | ❌（导出真的复制了它，是 `git add` 漏的） |

**没有任何一道闸问过"导出的内容到得了公开仓吗"。**
三道闸看的是源仓到导出树那一段，而这个缺陷发生在**导出树到公开仓**那一段 ——
一段此前没有任何守卫的路。

**修法两件**：
1. 把规则锚到根上（`/local/`），保住原意而不再误伤下层同名目录。
   更正是**整行**施加的，不是子串替换 —— 子串替换会把
   `infrastructure/local/` 改成 `infrastructure//local/`，
   而**一条修正规则不该制造它要修的那种错**；
2. 加**第 4 道闸**：把每一个导出路径喂给 `git check-ignore --no-index`
   （`--no-index` = 假装没有索引，只问规则，正是公开仓那一侧的处境），
   命中就拒绝导出。`-v` 会把命中的那条规则一起打出来，
   所以报错是 `infrastructure/local/compose.yml <- ignored by .gitignore:48:local/` ——
   **直接指着那一行**，不用人去猜。

这一条的教训不是"gitignore 的锚定规则很微妙"（那是细节），
是：**每一段没有守卫的路，迟早会在那一段上出事。**
而这一段特别阴险，因为它在流程的最后一步 ——
前面每一个指标都是绿的，唯一的信号是两个数差了 1。

## 六点五 · 第 12 条：为「别写死名字」而建的表，自己有两处写死了名字

这一条是在给离线演示接线时撞到的，而它**本来会让「不需要 key、不需要联网」
这句话当场不成立**。

上一批给配置层加了一张表，专门回答「这一支模型供应商是离线的吗」：

```python
OFFLINE_MODEL_PROVIDERS = {"mock": "...", "scripted": "..."}
```

它的注释写得很清楚，**查表而不是逐个 `or`**：

> 下一支离线实现加进去时，要么进表要么没这道闸，
> 而「忘了加一个 or」在代码里长得和「有意不挡它」一模一样。

**然后 `worker/cli.py` 里有两处没进表**，两处都写着
`if settings.model_provider != "mock":` —— 一处装配成本账，一处装配知识检索。
`scripted` 进表之后，这两行**没跟着改**。于是用回放替身跑整条链路时：

1. **装配了成本账** —— 给一次零成本的回放记一笔编造的账，
   而那段注释说的正是「记录一笔编造的成本会污染总额」；
2. **装配了知识检索**，而它内层是 `HttpxChatTransport(httpx.Client())` ——
   **一个真的会去调嵌入端点的 HTTP 客户端**。

第 2 条才是要紧的那条：演示的整个卖点是「不联网」，
而它会在第一次检索请求上**去连真实供应商**。
测试里 `pytest-socket` 拦得住这件事；**真跑演示的时候没有那道闸。**

**这一条的形状与第 3 条同源：一个半边凭记忆复述另一个半边。**
表建在配置层，而这两行**在表外面**，所以表上那句警告管不到它们 ——
**一条只写在注释里的纪律，管不住不读那条注释的代码。**

**修法**：两处都改成 `not in OFFLINE_MODEL_PROVIDERS`，并补一条守卫。
判据不是「今天这两行长什么样」，而是
**这个文件里不许出现把某一支离线供应商单独点名的比较** ——
下一支离线实现进表时，不需要有人记得来改这里。

> 这条守卫自己还有一个坑值得记：本仓纪律要求更正**不删原文**，
> 于是那段撤销注记**逐字引用了**旧代码 `!= "mock"`，
> 而一条按纯文本搜的守卫会把那段散文当成违规。
> **那种假红最后一定会以「把守卫改松」收场，而那比没有守卫更糟** ——
> 所以守卫改成按 token 判：丢掉注释与 docstring，只看真正会执行的那部分。

## 七 · 几个设计决定，和它们的理由

这些不是缺陷，是取舍。写出来是因为**理由比结论有用**。

### 回放替身录的是"模型侧产出"，不是 HTTP 响应体

要让人不用 API key 就能看到整条链路跑完，就需要一个回放替身。
最直觉的做法是录下 HTTP 响应体再放回去。**这里没有这么做。**

录的是**模型侧产出**，并且按"**真实供应商被要求遵守的那份 schema**"校验；
平台自有的那些字段（schema 版本、事件 id、来源、证据、两个 uuid）
由替身**回填**，走的是与生产代码**逐字同一条路**。

好处是一句话：**场景文件不可能漂成生产产不出来的形状。**
录 HTTP 响应体做不到这件事 —— 它只保证"当年那个供应商这么答过"。

### 轮次序号不用自增计数器

替身要知道"现在是第几轮"。计数器是最简单的写法，而**这个系统有重试**：
一次重试会让计数器静默取到下一轮的脚本。

所以序号是"**这通对话见过的事件 id 个数**"，而同一轮里的三步
都按同一个事件 id 回查 —— 于是一轮三步必然同序号，重试也不会错位。

### 脚本演完就拒，不回绕

脚本放完之后，替身**抛错**，走现成的那条安全阀。

**一个会静默回绕的演示会让人以为系统在回应，而它只是在复读。**

### 两个测试替身，不是一份事实的两份拷贝

这个仓里有两个模型替身。看起来很像，**合并它们是错的**。

* 一个的判据是"**不改变别人的断言**" —— 一百多条用例的期望挂在它身上。
  它的提交记录里写着：第一版给"这一轮该沉默"那种情况挑了个错的动作，
  **全量门禁红了 148 条**；
* 另一个的判据是"**忠实回放一段录好的决策文档**"。

**它们因为不同的原因而改变。** 共用一个实现，就等于把两个独立的变更理由
绑在一根绳上 —— 下一次为了演示去调它，一百多条用例会跟着红。

### 脱敏是"导出"，不是就地改

就地删敏感文件再公开有一个无法补救的问题：**git 历史会留着。**
删掉再 push，内容仍然可以从历史里取回来，**而一次公开无法撤回**。

所以公开仓必须是**一棵干净的树 + 全新历史**；
而原仓是职务作品，**应当保持原样**。

### 一句注释没有执行者，等于没有这句注释

渠道适配层的模块文档里写着一句：
*"nothing in the test suite is allowed to open a socket."*

而依赖声明里**没有任何东西执行它** —— 没有 socket 守卫，没有 HTTP 录制库。
一句约束写在最该遵守它的那个模块里，**而它只是一句话**。

修法是装上执行者（`pytest-socket` + 只放行回环），
并且让钉这道闸的用例**真的去连一次**外部地址确认它拦得住。
原来那句话同时被**收窄成它真正成立的方向**（拦连接、拦非回环、只管本进程），
而更正按"不删原文"留在原处 —— 读到旧注释的人要能看出它是**被更正的，
不是被遗漏的**。

## 八 · 最后一条，也是我最在意的一条

> **写下你没有核的那些，和你核过的一样重要。**

这个仓的每一份交接文档末尾都有一张两列的表：**"自己跑的"** 和 **"没核过"**。
不是免责声明 —— 是**下一轮的工单**。

上面第 3 条那 25 条红就是从那张表里捡出来的：
前一轮把"导出树跑起来是不是绿的"**诚实地标成了"没核过"**，
而它一跑就是 25 条红。

如果那一行当时写的是"应该是绿的"，这 25 条会跟着公开仓一起发出去,
而面试官会先看到一个红着的测试套件。

**一条红着的用例给人看，比少一个文件糟得多。**

配套的还有两条硬规矩：

* **凡在文档里写"已执行""已落地""某物今天不存在"的，必须给出一条能验证它的
  命令，并写明验证时的基线 commit；读到这类断言时当场重跑那条命令。**
  这条防的是这个仓最贵的一类错误：**声明了但不存在**。
  曾经实测到过一次：一份设计文档声称的四项留痕里前三项在分支尖端 0 命中,
  而同一笔提交的说明里写着"等排期批准后再动"——
  **文件与它自己的提交说明互相打架，而留下来的是说"已执行"的那份**;
* **这类断言尽量配一条会在它失效时变红的守卫。**
  这个仓里有一条我很喜欢的用例，它断言"某张台账今天还不存在",
  而一旦迁移目录里出现那张表的建表语句，它就红，并指着常量说"改我"。

写这份 README 的时候我也撞到了同一件事：我写下"这个仓的公开版本没有 README",
然后按规矩跑了一遍验证命令 —— `git ls-files | grep -i readme` 返回 **4 条**。
它们全是子目录的 README，根目录确实没有，**所以结论成立而我的说法不精确**。
改成了精确的说法，并把验证命令写进了那句话旁边。

那次更正花了大概两分钟。**这就是这套纪律的全部成本。**
